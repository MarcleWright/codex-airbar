# Development Setup

## Prerequisites

- Windows.
- Node.js and npm available on `PATH`.
- Local Codex state under `%USERPROFILE%\.codex`.

## Install

```powershell
npm install
```

## Run

```powershell
npm start
```

`npm start` builds the Vite renderer and then launches Electron.

Alternative Windows launcher:

```powershell
.\start-codex-airbar.bat
```

The launcher checks whether npm is available and whether Electron is installed. If Electron is missing, it runs `npm install`.

For renderer-only development:

```powershell
npm run dev
```

For Electron pointing at the Vite dev server, run the Vite server first and then:

```powershell
npm run dev:app
```

## Common Troubleshooting

### Electron failed to install correctly

This can happen when `npm install` times out while downloading Electron. Stop leftover `npm` or `node install.js` processes, remove `node_modules\electron`, then reinstall.

```powershell
Remove-Item -LiteralPath .\node_modules\electron -Recurse -Force
npm install electron@31.7.7 --save-dev
```

### App closes too quickly

Use `start-codex-airbar.bat` so the terminal pauses on startup failure.

### Logs

Electron app log:

```text
%APPDATA%\codex-airbar\codex-airbar.log
```

## Packaging Plan

Current development runs from source with Electron and Vite. The preferred first distribution target is a Windows `portable` executable.

Recommended packaging approach:

- Use `electron-builder`.
- Keep `portable` as the primary target.
- Defer installer packaging until tray/startup behavior is stable in real use.

Recommended packaging scope:

- include `.protected-src/**/*` generated by `npm run protect:main`
- include `dist/**/*`
- include `assets/**/*`
- include `package.json`
- use `assets/icon.ico` for the Windows executable icon
- keep `asar` enabled so packaged app files are bundled into `app.asar`

Core-code protection:

- `npm run protect:main` obfuscates the Electron core files into `.protected-src/`.
- `npm run pack:win` and `npm run dist:portable` run the protection step before invoking `electron-builder`.
- The packaged app entry is rewritten to `.protected-src/main.js` through `build.extraMetadata.main`.
- This is an anti-tamper / anti-casual-reading layer, not true encryption. A determined user can still inspect Electron packages, so secrets must not be embedded in the client.

Recommended output behavior:

- double-click launch without a terminal window
- main Airbar UI runs as a normal GUI app
- session `resume` may still open a terminal intentionally because that action launches Codex CLI by design

Suggested future scripts:

```powershell
npm run protect:main
npm run pack:win
npm run dist:portable
```

Suggested first builder targets:

- `portable` for everyday use and quick sharing
- optional later `nsis` installer if startup integration or standard install/uninstall becomes important
